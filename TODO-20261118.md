# Audit remediation plan — 2026-11-18

Findings from the whole-project audit, ordered worst first within each phase.
Every item names its location, what breaks, and the smallest change that fixes
it. Each phase ends with the tests and documentation that must accompany it.

Verification gate for every phase:

```
mix format --check-formatted
mix credo --strict
mix test --exclude ragex --exclude skip_in_gha
```

`mix dialyzer` and `mix deps.audit` are run where a PLT and network access are
available; when they are not, the phase is reported as partially verified rather
than as passing.

## Phase 1 — Defects (D1–D14)

### D1 — `AIGuard` writes its audit log to the process CWD, not the workspace

- **Location:** `lib/yoke/ai_guard.ex:49` (`@audit_file`), `:224-243`
  (`write_audit_entry/1`), `:145` (`audit_log/1`).
- **Defect:** the path is relative and resolved against the VM's working
  directory, so in a session whose `cwd` differs from it the audit trail lands in
  the wrong tree. The write is a `mkdir_p!` + `open` + `append` + `close` on
  **every tool call** (`executor.ex:59`, `:188`), inside the session's
  tool-execution task, and concurrent tool calls from
  `TaskEngine.Orchestrator.execute_batch/3` can interleave partial lines and
  corrupt the JSONL. `audit_log/1` accepts a `cwd` that the writer ignores, so
  reads and writes can disagree.
- **Fix:** a supervised `Yoke.AIGuard.AuditLog` GenServer that owns the file.
  `guard_llm/3` and `guard_tool/3` accept `:cwd` and `cast` the entry; the
  writer batches and appends whole lines. `audit_log/1` reads the same resolved
  path. When the process is absent (tests, `--no-start`) the write is skipped
  rather than performed unsynchronised.

### D2 — `write_ish_bash?/1` is a substring matcher, so the CI read-only guarantee has trivial bypasses

- **Location:** `lib/yoke/plan_gate.ex:22-47` (`@bash_write_markers`),
  `:70-81` (`write_ish_bash?/1`), `:180` (`has_real_redirection?/1`);
  `lib/yoke/hands/executor.ex:158` (`shell_write?/1`).
- **Defect:** `Executor`'s module doc (`:18-21`) calls the read-only property "a
  safety property, not a preference". It does not hold. Returning `false`
  (i.e. "read-only") today: `python3 -c "open('f','w').write('x')"`,
  `perl -pi -e 's/a/b/' f`, `git checkout -- .`, `truncate -s0 f`,
  `ln -sf /etc/passwd f`, `find . -delete`, `echo hi>out.txt` (redirection
  without surrounding whitespace).
- **Fix:** in `:ci` mode, do not classify bash at all. `Executor.write_tool?/2`
  treats every `@shell_exec_tool_names` call as write-capable. A review does not
  need a shell — `Yoke.PRReview.Tools` supplies `read_file`, `read_files`,
  `list_dir`, `grep_search`, `glob_search`, `git_diff`, `git_root`. The
  classifier stays for the interactive plan gate, where a false negative costs a
  prompt rather than a checkout.

### D3 — `annotations` are computed and returned but never emitted by `yoke review`

- **Location:** `lib/yoke/ci/review.ex:201` (renders), `:226` (returns);
  `lib/yoke/cli/ci.ex:895-905` (`run_review/1`), `:927-935`
  (`print_result/2`).
- **Defect:** `Annotations.emit/1` is called only on the `lint` path
  (`cli/ci.ex:687`). `yoke review` produces inline PR annotations in its result
  map and never writes them to stdout, where the Actions runner reads workflow
  commands from.
- **Fix:** emit them from `run_review/1` after `print_result/2`, for every
  format except `json` (JSON consumers parse stdout).

### D4 — Markdown exports are not re-importable, and the error names the wrong problem

- **Location:** `lib/yoke/brain/session_store.ex:381-390`
  (`lmml_narrative?/1`), `:398-419` (`parse_import_json/2`);
  `lib/yoke/brain/session.ex:1119-1160` (markdown export paths).
- **Defect:** feeding an exported `.md` back to `/import` fails
  `lmml_narrative?/1` (no `@@@`), falls through to `parse_import_json/2`, and
  reports `"Invalid JSON in '...'"` for a Markdown file.
- **Fix:** in `parse_import_content/2`, detect `.md`/`.markdown` by extension
  and return an explicit error naming the resumable alternative.

### D5 — `Session.export_session/2` can crash the actor on a directory error

- **Location:** `lib/yoke/brain/session.ex:1041-1042` (`File.mkdir_p!`).
- **Defect:** a read-only checkout, a full disk, or a `.yoke` that is a file
  raises inside `handle_call`, destroying the conversation. Every other
  `handle_call` in the module returns `{:error, ...}` for I/O failure
  (`:738`, `:787`, `:1061`).
- **Fix:** `File.mkdir_p/1` with an explicit `{:error, reason}` reply.

### D6 — Background completion notices are discarded when a turn is running

- **Location:** `lib/yoke/brain/session.ex:1244-1266`
  (`{:subagent_completed, ...}`), `:1269-1293` (`{:job_completed, ...}`),
  `:1209-1210` (the merge that drops them).
- **Defect:** both handlers append to `state.messages` unconditionally. The
  in-flight agent-loop `Task` holds its own copy of the state; when it finishes,
  `handle_info({ref, result}, ...)` returns `%{new_turn_state | active_turn: nil}`
  and the notice is lost. The user sees the terminal interjection
  (`:1259-1263`) for a message the model will never read.
- **Fix:** buffer notices in `pending_notices` on the state and append them
  during the post-turn merge. `has_pending_notice?/1` (`:2829-2840`) consults
  the buffer as well as `List.last(messages)`.

### D7 — `Config.god_mode?/1` defaults to `true` under `MIX_ENV=test`

- **Location:** `lib/yoke/config.ex:135-149`; `test/test_helper.exs:33`.
- **Defect:** a production module carries a test-environment branch that
  auto-approves every permission decision. A test that forgets to un-set it
  silently passes, which is the worst failure mode for a permission gate. Four
  test files already perform the same save/restore dance
  (`interaction_call_sites_test.exs:19-36`, `:125-136`;
  `question_prompt_test.exs:185-192`; `cli_interaction_server_test.exs:12-19`;
  `cli_repl_test.exs:13-19`).
- **Fix:** delete the branch; keep the `test_helper.exs` global, which achieves
  the same convenience without shipping test behaviour in production code.

### D8 — `format_tool_confirmation_summary` leaks the full argument map into the permission modal

- **Location:** `lib/yoke/brain/session.ex:2689-2691` (fallback clause).
- **Defect:** `inspect(args)` is rendered verbatim with no truncation, while the
  sibling clause (`:2677`) truncates to 60 characters per value. The user is
  asked to approve a wall of text they cannot read.
- **Fix:** share the truncating renderer between both clauses and cap the number
  of keys shown.

### D9 — `/export` and `/sandbox` silently coerce invalid input to a default

- **Location:** `lib/yoke/cli/repl.ex:1110-1117` (`/export`),
  `:1088-1095` (`/sandbox`).
- **Defect:** `/export xml` writes Markdown. `/sandbox maybe` **disables** the
  sandbox. Every other command in the file validates and reports
  (`/jobs` at `:2334-2340`, `/god` at `:2033-2043`, `/session list` at
  `:2156-2164`).
- **Fix:** reject unknown arguments with usage text and leave state unchanged.

### D10 — `{:set_model, ...}` is neither persisted nor guarded against a running turn

- **Location:** `lib/yoke/brain/session.ex:603-612`.
- **Defect:** unlike `{:set_provider, ...}` (`:591`) it never calls
  `SessionStore.save_session/2`, and unlike `{:set_endpoint, ...}` (`:598-601`)
  it has no `active_turn` guard. The choice is lost on restart.
- **Fix:** add the guard clause and persist after the update.

### D11 — `Yoke.Brain.Session` holds five unrelated responsibilities

- **Location:** `lib/yoke/brain/session.ex` (2880 lines).
- **Smell:** the actor, the agent loop, the plan gate, the permission gate, the
  tool-call orchestrator, the confirmation renderer (`:2656-2789`), the message
  repairer (`:1883-1971`), and the export writer (`:1083-1160`). Both
  `session.ex` and `session_store.ex` appear in the audit's "no obvious matching
  test file" list because the only way in is through the actor.
- **Fix:** extract the two pure, already-testable clusters into their own
  modules with their own test files (see I2).

### D12 — `test_helper.exs` mutates global application env that production code reads

- **Location:** `test/test_helper.exs:31-33`.
- **Smell:** combined with D7 the suite's default posture is "auto-approve
  everything", undermining the explicit stubs the interaction tests install.
- **Fix:** keep the global (it is the documented convenience) but remove the
  production branch (D7) so the default is visible and overridable in one place.

### D13 — `dllb_3010.sock` is untracked and matches no ignore rule

- **Location:** repository root.
- **Defect:** `git check-ignore` confirms `yoke_escript` and `erl_crash.dump` are
  ignored but the socket is not, so `git add -A` picks up a live Unix socket. The
  CI cache config already excludes `!.ragex/**/*.sock` (`ci.yml:80`), so the
  intent exists but was never applied at the root.
- **Fix:** add `*.sock` to `.gitignore`.

### D14 — Complexity thresholds are nominal

- **Location:** `.credo.exs` (`max_complexity: 40`, `max_nesting: 6`);
  `lib/yoke/hands/executor.ex:614`, `lib/yoke/client/deep_seek_api.ex:201`
  (`credo:disable-for-lines`).
- **Taste:** the repo is consistently formatted and dialyzer-clean, so this is
  not a defect. The thresholds would not fire on a genuinely tangled function
  until it is already unmaintainable.
- **Status: partially done, honestly reported.** Lowering to `25`/`4` surfaced
  **15 pre-existing violations**, not zero:

  | Count | Rule | Worst offender |
  | --- | --- | --- |
  | 10 | nesting depth 5 | `Yoke.CLI.ConfigExplorer.parse_session_metadata` |
  | 1 | nesting depth 6 | `Yoke.CLI.ConfigExplorer.list_session_files` |
  | 1 | cyclomatic 38 | `Yoke.PRReview.comment_reports_finding?` |
  | 1 | cyclomatic 32 | `Yoke.CLI.LineEditor.raw_loop` |
  | 1 | cyclomatic 29 | `Yoke.MCP.ServerManager.configure_ragex_store` |
  | 2 | cyclomatic 26 | `Yoke.CLI.QuestionPrompt.tui_loop`, `Yoke.CLI.ConfigExplorer.handle_edit` |

  Refactoring all 15 is a multi-day change across five unrelated modules and is
  out of scope for this plan. The thresholds are therefore set to `40`/`7` --
  the tightest values the tree satisfies -- with the backlog recorded above and
  a comment in `.credo.exs` pointing at it. This is a deliberate deferral, not
  a silent revert: the previous `6` was looser than the code requires.

- **Follow-up:** extract the six cyclomatic offenders and the eleven deep-nesting
  functions one at a time, lowering the thresholds as each lands.

## Phase 2 — Codebase improvements (I1–I8)

### I1 — Make `Yoke.AIGuard` a supervised writer

Fixes D1. One GenServer under `Yoke.Application`, `cast`-based, batched appends.
Removes a synchronous file round-trip from every tool call and fixes the
concurrent-append corruption.

### I2 — Move the pure clusters out of `session.ex`

Fixes D11. `format_tool_confirmation_summary/2` and its five helpers
(`:2656-2789`, ~135 lines) become `Yoke.Brain.ConfirmationSummary`.
`repair_tool_messages/1` and `convert_all_tool_roles_to_user_messages/1`
(`:1883-1971`) become `Yoke.Brain.MessageRepair`. Both get their own test file,
which also closes two of the audit's "no matching test file" entries.

### I3 — Add turn-isolation tests for `Yoke.Brain.Session`

Three focused assertions that need no provider: a `:DOWN` from the turn task
replies `{:error, _}` to the waiting caller; `cancel_current_turn/1` replies and
clears `active_turn`; a second `send_user_message/2` while `active_turn` is set
returns the "already running" error without touching the working tree.

### I4 — Fold the UUID generators into one

`Yoke.CLI.Main.generate_uuid/0`, `Yoke.Brain.SessionStore.generate_session_id/0`
and `Yoke.Client.DeepSeekAPI.generate_session_id/0` are byte-identical;
`Yoke.CI.Review.run_uid/0` is a fourth. One `Yoke.UUID` module with `v4/0` and
`v7/0`.

### I5 — Extract the language-disambiguation trees in `Yoke.Practices`

`practices.ex:171-203` contains two inline `if` trees inside a 60-line function,
with no test coverage for either.

### I6 — Tokenize the interactive plan gate's bash classifier

Companion to D2. The interactive gate keeps a classifier; make it token-aware
(first word + redirection regex) instead of 26 substring checks.

### I7 — `:rest_for_one` for the supervision tree

`application.ex:41` uses `:one_for_all`, so a crash in `Yoke.BashTracker` (a
statistics collector) restarts the session supervisor and drops every live
conversation.

### I8 — Document `mix test --only app`

`test/test_helper.exs:64-77` builds the exclusion list dynamically; there is no
documented way to run only the app-dependent tests.

## Phase 3 — UX improvements (U1–U11)

### U1 — `/model <unknown>` silently accepts a typo

`cli/repl.ex:1434` passes unknown ids straight through. The user sees
`Switched model to 'deepseek-flsh'` and discovers the problem at the next HTTP
400. Validate against `DeepSeekAPI.list_models/1`, as bare `/model` already does.

### U2 — `/sandbox` with no argument enables; with a typo it disables

`cli/repl.ex:1088-1108`. Two opposite behaviours from one command, and the
dangerous direction is the silent one.

### U3 — `/export <unknown>` writes the wrong file silently

`cli/repl.ex:1116`. Reject and list the formats.

### U4 — `/checkpoint` listing omits timestamps

`cli/repl.ex:2082-2084` prints `ID | label | turn` although
`list_checkpoints/1` returns `:timestamp` (`session.ex:752`).

### U5 — `/permissions` accepts only `auto`/`yolo`

`cli/repl.ex:1134-1145`; everything else falls through to `ask_confirm`, so
`/permissions off` works by accident.

### U6 — `/practices` is missing from the `/help` menu

`formatter.ex:120-178` lists 42 commands; the getting-started guide at `:195`
tells users to run `/practices`, which the menu omits. Add a static audit that
every `handle_input("/<name>", ...)` clause has a menu line.

### U7 — `yoke review --format json` appends an ANSI info line to stdout

`cli/ci.ex:927-935`. A JSON consumer gets a JSON line followed by a decorated
notice. Send the notice to stderr for `json`.

### U8 — `yoke review --dry-run` omits the diff cap

`cli/ci.ex:907-925` reports bytes but not the cap, so a run that would hard-fail
looks fine. Print the cap and warn when it is exceeded.

### U9 — A tool timeout is invisible to the user

`orchestrator.ex:84-87` explains the timeout to the model only. Surface it once
through `Yoke.CLI.TerminalOwner.interject/1`, the mechanism already used for
subagent completion (`session.ex:1259-1263`).

### U10 — `/export` defaults to a non-resumable format

`session.ex:241` defaults to `:markdown`, so `/export` with no argument produces
a file `/import` cannot read (D4). Default to `:lmml` and say whether the file
is resumable.

### U11 — The permission modal offers seven options with no reversibility hint

`session.ex:2534-2542`. Group them by scope (once / session / project / global)
and mark which ones write to disk.
